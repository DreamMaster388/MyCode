# Spec: SWE-bench Lite 评测容器专用工具路径校验（来自 intent.md）

作者：lyd。状态：已批准。

一句话：五个容器文件工具在容器内先校验路径再读写，默认 trusted 语义，`--no-path-guard` 可整体关闭。

## 需求
R1 容器内 Read/Write/Edit/Grep/Glob 在真正读写前完成路径校验，不得只在宿主机判断。
R2 默认策略与本地 trusted 语义一致：全盘可读；仅 `/testbed`、`/dev/null`、`/tmp` 可写。
R3 越界访问直接拒绝，返回 `ACCESS_DENIED` 与统一拒绝标记，不进入审批。
R4 相对路径、绝对路径、`..`、软链及尚不存在的写目标都按容器内 realpath 判定，软链逃逸视为越界。
R5 `eval/run_predictions.py` 新增 `--no-path-guard`：默认开启校验，显式传入时关闭并恢复当前行为。
R6 开关只作用于五个文件工具；Bash、补丁提取、网络与工具接口不变。

## 风险与分歧
C1 Bash 不在校验范围，仍可访问任意路径并绕过文件工具边界 → 已定：只保证文件工具口径一致，不宣称安全隔离（lyd）。
C2 全盘可读使 Read/Grep/Glob 不会因越界被拒 → 已定：按 trusted 语义，校验主要约束写（lyd）。
C3 校验与执行之间存在极短时间窗，容器内无并发对抗 → 已定：接受，与本地工具同口径。

## 设计
- 新增容器侧路径守卫，携带纯判定逻辑；由 DockerSandbox 在容器内执行，先于对应文件操作，不依赖宿主机路径解析。
- 守卫用 realpath 归一目标身份，按路径分量判断是否位于可写根内；写目标不存在时按父目录判定，避免前缀误放行。
- Read/Write/Edit/Grep 校验其 `path`；Glob 同时校验起始目录与模式解析出的访问范围。
- 拒绝响应沿用本地标记与错误码，文案只说明越界，不提示绕过。
- DockerSandbox 增加守卫开关；关闭时完全不注入守卫逻辑，命令与返回保持现状。
- `run_predictions` 的开关沿编排链传到工具构造；诊断记录本次开关状态，便于区分实验组。
- 配套单测覆盖可写边界、软链逃逸、`/tmp` 与 `/dev/null` 放行、开关关闭；不改工具签名与返回结构。

## 不在范围
- Bash 命令内路径校验。
- 拒绝次数统计与 diagnostics 指标扩展。
- 容器内内核级沙箱（Landlock/bwrap）。
