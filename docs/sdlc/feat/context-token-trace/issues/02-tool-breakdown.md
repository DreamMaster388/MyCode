# 02: 工具区

**要构建什么：** 一次 run 结束后，会话元数据里除类别区外，还能按工具名看到每个工具消耗的输入 token 和调用总次数；工具名覆盖 Read/Bash 等已注册工具，也覆盖模型臆造的未知工具和参数解析失败的调用。工具区只是第二视角，不改变类别区数值。

**阻塞于：** 01

**状态：** ready-for-agent

- [ ] `context_usage.tools` 每个出现过的工具名一行：`input_tokens` 为该工具调用参数与 tool 结果在请求中的输入 token 之和，`calls` 为模型发出的该工具 tool_call 总数。
- [ ] 同一 assistant 消息多个 tool_call 时按参数长度分摊参数份额；tool 结果按 tool_call_id 映射到工具名；未知工具名原样保留。
- [ ] 参数解析失败与未知工具也计入 calls 和对应 token；不区分成功/失败/未知/参数错误，不含 LLM HTTP 重试。
- [ ] 工具区数值从 assistant 与 tool_result 类别中抽取，不改变类别区；工具 schema 只进 tool_schema 类别。
- [ ] 工具调用参数生成时的输出 token 不计入工具区；只算后续请求中重发的输入。
- [ ] 测试用假 LLM 与假工具覆盖多工具、未知工具、参数错误、结果映射与重发累计；不联网、不执行真实工具。
- [ ] 现有总量/步数/请求次数与类别区口径不变。
