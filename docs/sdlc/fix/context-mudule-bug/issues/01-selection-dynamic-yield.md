# 01: 摘要选区：不足轮数不崩，保留区逐轮让出

**要构建什么：** 摘要触发时，选区按可见 assistant 轮数 A 切：A < 2 不摘要并原样返回视图；A ≥ 2 时保留 min(N, A-1) 轮，严格从倒数第 keep 条 assistant 开始，压缩区非空、保留区至少 1 轮，不再回退到 user。保留区自身仍超阈值时，后续 build 逐轮让出最旧一轮，直到只剩 1 轮或低于阈值；不再出现 IndexError 或空压缩区摘要。

**阻塞于：** 无（可立即开始）

**状态：** ready-for-agent

- [ ] 触发后 A < 2：不调用摘要 LLM、不 append 摘要、不产生 outcome，返回遮蔽后的完整视图（含旧摘要）。
- [ ] A = 2：保留 1 轮，压缩区包含该 assistant 的 user 请求，保留区从该 assistant 开始。
- [ ] A ≤ N：每次触发让出最旧 1 轮；连续超阈值时逐轮让出，不产生空压缩区摘要，最终停在 1 轮并跳过。
- [ ] A > N：保留 N 轮，压缩其余可见消息；保留区不以 user 开头时也不回退。
- [ ] 有旧摘要：走增量摘要，摘要区间包含旧摘要与压缩区；无旧摘要：普通摘要只输入压缩区。
- [ ] 纯选区接口只处理 A ≥ 2，不修改输入列表或消息对象；A < 2 由 builder 拦截。
- [ ] 覆盖 A=2、A≤N、A>N、有/无旧摘要、输入不可变；替换旧的“回退到 user”用例；context/core 测试通过，不联网、不调用真实模型、不写 trace。
